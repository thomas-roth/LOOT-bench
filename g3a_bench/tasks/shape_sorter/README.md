# Shape-sorter task category

Insert every piece into its matching hole in a free-standing, hollow sorter
cube. Each piece fits only its own hole.

A *variant* (`variants.py`) fixes the shape set (tail-extending: ShapeSorter3's
shapes are shapes 0..2 of ShapeSorter5) and how the cube spawns. The cube and
every piece are free bodies (STL/XML assets under `xmls/`, generated by
`xmls/make_sorter_assets.py`); `xmls/sorter_layout.json` is the single source
for both the hole geometry and the success metric. The `ShapeSorterCommand`
re-derives every hole's mouth/axis from the cube's live pose each step for the
success metric; the policy itself observes only the cube's own pose
(`cube_pose`) and infers hole positions from it, since every hole is a fixed,
learnable offset from the cube.

A piece counts as inserted the first step it crosses from outside its own
hole's mouth to past the inner wall plane (`SorterLatch`, a latched
mouth-plane crossing that survives the piece tumbling around inside the
hollow cube afterwards) — no shape piece fits into a foreign hole. Success
holds once every piece has latched in and the gripper is open (there is no
at-rest requirement: the free cube and its inserted pieces may keep
settling/tumbling after latching).

## Cube spawn

- `FixedOrientation`: the cube always drops in the same deterministic pose
  (star-face down — the star socket is never used by this category — so no
  required hole ever starts against the table); only its xy position is
  jittered.
- `NoRotation`: the cube drops face-down on one of the faces whose hole is
  *not* needed this variant, plus a random yaw — still solvable without
  reorientation, but the allowed-face set shrinks as more shapes are
  required.
- `Full`: the cube drops face-down on any of its six faces plus a random yaw
  — a required hole may start facing the table, so reorienting the cube may
  be necessary.
- `RandomPositions`: same deterministic cube pose as `FixedOrientation`, but
  pieces spawn on a wide ring of cells around the cube instead of the near
  band the other variants use.

## Observations (state-based)

- joint positions/velocities, EE pose, last action
- the cube's own pose (env-local position + quaternion) — a single pose for
  the whole rigid cube/hole assembly; every hole's position/orientation is a
  fixed, learnable offset from it, so no per-hole observation is added
- all piece poses (env-local position + quaternion, object-major)
- per-socket latched flags
- no raw command observation (`command_obs=False`): the cube's pose above
  already gives the policy everything needed to infer hole poses

## Rewards

- `progress`: fraction of pieces latched into their own hole, in [0, 1]
- `success`: bonus while every piece is latched and the gripper is open

## Variants

| Task id (`-Dk1_uni`)                                | Description                                     |
| ----------------------------------------------------- | ------------------------------------------------ |
| `G3A-Sorter-{3,4,5}Shapes-FixedOrientation`            | cube pose fixed, position jittered          |
| `G3A-Sorter-{3,4,5}Shapes-NoRotation`                  | cube face-down on an unneeded hole + random yaw |
| `G3A-Sorter-{3,4,5}Shapes-Full`                        | cube face-down on any face + random yaw     |
| `G3A-Sorter-{3,4,5}Shapes-RandomPositions`             | fixed cube pose, pieces spawn on a wide ring |

Play e.g. with:

```bash
uv run g3a-play G3A-Sorter-3Shapes-FixedOrientation-Dk1_uni
```
